# How MetaObjects is used here

A guided tour of the metadata spine for a curious engineer. [`architecture.md`](./architecture.md)
is the *app* doc; this is the *MetaObjects* doc. Everything below is grounded in real files.

## The one idea

Typed metadata under [`metaobjects/`](../metaobjects/) is the durable spine. Every generated
file under `src/**/generated/` is disposable output — regenerated by `npm run gen:db`
(`meta gen`) and diffed by `npm run demo:drift` (`meta verify`). You never hand-edit generated
code; you change the metadata and regenerate.

Two object kinds matter (ADR-0028):

- **`object.entity`** — owns data: has identity + a `source.rdb`, so it becomes a **DB table**.
  Only `Council` and `CouncilTurn` are entities here.
- **`object.value`** — a pure shape with no identity and no source: an **interface + Zod schema**,
  never a table. Everything else (`WizardOutput`, `TurnLens`, the prompt payloads, …) is a value
  object — the in-memory shapes for prompts, LLM I/O, and projections. `storage: jsonb` is a
  *column* attribute, so it's meaningful on an entity field and inert on a value object.

## One field, followed to every surface

Take `WizardOutput` (the structured thing each wizard emits) declared in
[`metaobjects/meta-wizard-output.yaml`](../metaobjects/meta-wizard-output.yaml). Its `stance`
field `extends` the shared abstract enum `wizardStance`
([`abstracts/meta-stance-enums.yaml`](../metaobjects/abstracts/meta-stance-enums.yaml)) — declared
once, reused by `WizardOutput`, `TurnLens`, and `CouncilTurn`. From that one spine:

- `entityFile`/`queriesFile` emit `src/db/generated/WizardOutput.ts` (Zod) and, for the
  *entities* that persist these fields, Drizzle tables + typed finders. Because several fields
  share `wizardStance`, codegen also emits a single `src/db/generated/enums.ts` the entities
  reference — the de-duplication carries through to the generated code.
- `promptRender` emits a typed render payload + handles in `src/render/generated/prompts.ts`.
- `structuredCompletion` (a custom generator) reads the `template.toolcall` that names
  `WizardOutput` as its `payloadRef` and emits `callEmitWizardTake` in
  `src/llm/generated/toolcalls.ts` — a wrapper whose runtime tool schema *is* the Zod
  `WizardOutputInsertSchema`.
- `sseFrames` (custom) emits the `wizard` arm of the `CouncilFrame` union in
  `src/web/generated/council-frames.ts`, carrying a `WizardOutput`.

Rename a field on `WizardOutput`, or on the `WizardUserPayload` that the prompts bind, and the
drift gate fails across all of it at once — the money shot in the [README](../README.md).

## The prompt pillar, end to end

1. **Payload** — a `object.value` payload (e.g. `WizardUserPayload`) declares exactly what a
   prompt may reference. Payload bloat becomes a reviewable diff.
2. **Declaration** — a `template.prompt`
   ([`metaobjects/prompts/`](../metaobjects/prompts/)) binds a payload to external text via
   `textRef`; the text lives in [`data/templates/`](../data/templates/) Mustache, *outside*
   `metaobjects/` (so `loadMemory()` doesn't try to parse it as metadata).
3. **Render** — `promptRender` generates a typed `render<Name>` handle. `mustacheTemplates`
   (custom) inlines the `.mustache` files into `src/render/generated/templates.ts` so the
   Worker — which has no filesystem — can resolve them via an `InMemoryProvider`.
4. **Compose** — [`src/council/prompts.ts`](../src/council/prompts.ts) is the seam where the
   generated handles meet hand-written composition. A byte-equivalence snapshot test pins the
   rendered output.
5. **Tool call** — `template.toolcall` + `structuredCompletion` generate `callEmitWizardTake` /
   `callEmitVerdict`: try → retry-with-stricter-reminder → optional typed fallback.
6. **Persist / display** — the entity codegen persists the take's columns to D1; the SSR share
   page ([`src/render/share-page.tsx`](../src/render/share-page.tsx)) reads the same generated types.

`meta verify --templates` checks that every `{{var}}` in a template is on its declared payload —
so a renamed payload field can't silently degrade a prompt.

## Extending the metamodel (it's a standard, not a framework)

[`src/codegen/wizardsofodd-provider.ts`](../src/codegen/wizardsofodd-provider.ts) registers this
project's own vocabulary, strict-provenance-clean (ADR-0023):

- **`template.streamFrame`** — a brand-new project-local subtype (MetaObjects core has no SSE
  concept). It pairs an `@eventName` with a `@payloadRef`; `sseFrames` walks these nodes.
- **`@retryReminder` on core `template.toolcall`** — a vendor attr *added to* a core subtype via
  `registry.extend`. The structured fallback payload rides the registered `attr.properties` bag
  (an undeclared `@fallback` would fail load under strict provenance — `ERR_UNKNOWN_ATTR`).

The three custom generators (`sseFrames`, `structuredCompletion`, `wizardRegistry`, plus
`mustacheTemplates` + `wizardData`) implement the same `Generator` interface as the built-ins,
each on a named `target` so the drift gate covers their output.

## The drift gate

- `npm run gen:db` (`meta gen`) regenerates everything to the committed locations.
- `npm run demo:drift` (`meta verify --templates --codegen --prompts data/templates`) checks
  **template drift** (`{{var}}` ↔ payload) and **codegen drift** (regenerate to a temp dir, diff
  the committed output).
- CI ([`.github/workflows/meta-verify.yml`](../.github/workflows/meta-verify.yml)) runs that exact
  command on every PR — CI and local are byte-identical.

## Friction log — what didn't work, honestly

Reference projects that admit friction are believed. Real things this project hit:

- **The drift gate had a blind spot.** Four generated files were written *outside* the
  drift-checked directories via `../../` path escapes, so a breaking wire-format change
  (`@eventName: wizard → wizardTake`) passed `demo:drift` clean. Fixed by declaring per-target
  output dirs and putting every generator on a `target` — now the diff walks the whole surface.
- **The official `meta-verify-action` only runs `--templates`.** It has no `--codegen` input, so
  it would miss codegen drift. CI runs `npm run demo:drift` directly instead, so the gate is complete.
- **Abstract-attr hoisting doesn't work for every subtype.** `field.enum` shares its `values`
  via an abstract + `extends` (see the stance enums), but `template.prompt` requires `@textRef`
  as an *own* attr — the loader's required-attr check is own-only — so an abstract `template.prompt`
  that omits `textRef` fails to load. The prompt declarations were consolidated into two files but
  keep their per-node `payloadRef`/`format`.
- **A nested-value-object FQN codegen bug** in an earlier `@metaobjectsdev/codegen-ts` surfaced
  from this project and was fixed upstream (the `promptRender` FQN handling in 0.15.18).
